# Telegram UI для Glossaryck

## Что изменилось

Статические экраны больше не генерируются моделью. Локальный плагин
`glossary-ui` перехватывает их на `reply_dispatch` — до раскрытия
workspace-скилла и до LLM — и сразу возвращает обычный текст с нативной
inline-клавиатурой Telegram. Router регистрируется типизированным SDK-вызовом
`api.on("reply_dispatch", ...)`: legacy `api.registerHook(...)` использует
другую сигнатуру обработчика и для этого маршрута не подходит.

Плагин обрабатывает:

- `/start` без параметров и `/menu` — главное меню, `/about` — отдельный экран;
- `/explain` — подсказку и примеры терминов;
- `/term` и `/term ROE` — подсказку либо готовую локальную карточку;
- `/knowledge` — выбор раздела и каталог;
- `/sources` — краткую политику источников и официальные ссылки.

`/digest` и `/analyze` намеренно остаются у агента. Им нужны веб-поиск,
отбор и суммаризация. Известный термин, отправленный обычным текстом, тоже
отвечается локальной карточкой; только неизвестный термин уходит агенту и RAG.
Карточки плагин читает напрямую из `workspace/memory/knowledge`.

## Как работают кнопки

- Плагин отдаёт нативную `channelData.telegram.buttons`, а не общий
  `presentation`. Общий Telegram-рендерер OpenClaw добавляет в текст fallback
  со всеми командами, поэтому меню дублировалось над клавиатурой.
- Навигация использует callback namespace `glossary:*` и редактирует текущее
  сообщение на месте: каталог не превращается в длинную ленту экранов.
- Нажатие на известный термин читает соответствующий Markdown-раздел и
  редактирует экран каталога в готовую карточку. LLM, `memory_search` и
  progress-заглушка для этого не запускаются.
- Если статья отсутствует или каталог временно недоступен, callback безопасно
  возвращается к маршруту `submitText: /start term_<payload>` через агента.
  В штатном каталоге CI заранее проверяет наличие каждой такой статьи.
- Кнопка дайджеста аналогично отправляет `/digest` агенту; ссылки источников
  остаются обычными URL-кнопками Telegram.
- В одном ряду не больше двух кнопок. На каждом вложенном экране есть путь
  назад и в главное меню.

Плагин не регистрирует второй набор Telegram-команд: видимым меню владеет
`channels.telegram.customCommands`, иначе OpenClaw сообщает о конфликте.
Вместо этого ранний router разбирает и простой `/start`, и аргументы вроде
`/start term_ROE`; известный термин также открывается без модели.

## GitOps-доставка

Исходник находится в `extensions/glossary-ui/`. На каждом reconcile пакет
синхронизируется в:

```text
${OPENCLAW_STATE_DIR}/config/extensions/glossary-ui
```

Плагин включён декларативно через `config/openclaw.batch.json`. Если изменился
его код или конфиг OpenClaw, reconcile один раз перезапускает gateway. Если
ничего не изменилось, пятиминутный таймер не прерывает диалоги рестартом.

## Проверка после выкладки

Проверить, что runtime увидел именно типизированный router:

```bash
sudo docker compose \
  --env-file /run/openclaw/env \
  -f /opt/openclaw-glossary/docker-compose.yml \
  exec -T gateway openclaw plugins inspect glossary-ui --runtime --json |
  jq '{status: .plugin.status, hookCount: .plugin.hookCount,
       typedHooks: .typedHooks, customHooks: .customHooks}'
```

Ожидается `status: "loaded"`, `hookCount: 1` и объект
`{"name":"reply_dispatch"}` в `typedHooks`. Обратите внимание: JSON-отчёт
называет поле `name`, хотя внутри registry оно называется `hookName`. В
`customHooks` этого события быть не должно. Команда `openclaw hooks list`
показывает legacy/internal hooks, поэтому отсутствие там старого
`glossary-static-ui-router` после этой правки нормально.

Затем проверить в Telegram:

1. `/menu` показывает четыре крупные кнопки без паузы на модель.
2. `База знаний` показывает 28 определений; нажатие на известный термин
   мгновенно редактирует текущее сообщение в карточку без 👀 и LLM.
3. `Источники` показывает кликабельные официальные сайты.
4. `Новости об ИИ` запускает существующий динамический дайджест.
5. `/start term_ROE` и текст `ROE` показывают одну и ту же карточку без LLM.
6. Только `/digest`, `/analyze` и неизвестный свободный запрос создают записи
   `provider-transport-fetch` в логах; `/menu` и `/knowledge` — нет.

## Тихий прогресс

Пока агент работает, Telegram показывает одну дружелюбную заглушку вроде
`🦞 Lobstering…` или `🔎 Ищу и проверяю…`. Названия инструментов, пути к
файлам, reasoning и итоговая строка `N tool calls` скрыты настройками
`streaming.progress.toolProgress: false` и `reasoningDefault: off`.

На входящее сообщение бот временно ставит реакцию `👀` и убирает её после
ответа. Финальный ответ остаётся обычным чистым сообщением.

Старый диалог может хранить собственные overrides поверх defaults. После
выкладки один раз отправьте в нём `/reasoning off` и `/verbose off`.
