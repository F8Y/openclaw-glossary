# Снимок проекта

Состояние на 12 августа 2026. Обновляется при заметных изменениях.
Нужен, чтобы входить в проект без чтения всей истории: что где лежит,
почему так сделано и чего не хватает.

Единственный документ по проекту. Только факты и принятые решения;
планов и оценок здесь нет.

---

## Что это

**Glossaryck** — Telegram-бот на OpenClaw. Объясняет термины ИИ и финансов
из своей базы, собирает дайджест новостей, разбирает релизы моделей.
Аудитория — один-два человека, включая председателя, для которого важнее
всего внешний вид и понятность.

MVP сдаётся 14 августа. После сдачи расходы прекращаются.

## Инфраструктура

| Что | Где |
|---|---|
| VM | Cloud.ru, Ubuntu, 4 ГБ / 30 ГБ |
| Рантайм | Docker Compose, образ запинен по digest |
| Репозиторий | `F8Y/openclaw-glossary`, ветки `master` → `deploy` |
| Клон на VM | `/opt/openclaw-glossary`, deploy-ключ только на чтение |
| Порт гейтвея | `127.0.0.1:18789` — наружу не публикуется |
| Telegram | `extra_hosts` пинит `api.telegram.org` на `149.154.167.220` |

Канал и его bundled-плагин включены декларативно двумя отдельными ключами:
`channels.telegram.enabled` и `plugins.entries.telegram.enabled`. На неявное
автовключение рантайма проект не полагается.

## Как выглядит доставка

```
git push master → CI → ручной Promote → ветка deploy
                                            ↓
        systemd-таймер раз в 5 минут → reconcile.sh
                                            ↓
   git reset --hard → SOPS в tmpfs → config → rsync → health-gate
```

Реконсиляция безусловная: состояние сервера приводится к ветке `deploy`
независимо от того, менялось ли что-то. Ручная правка на сервере
затирается — это задумано.

Если новый коммит меняет сам `deploy/reconcile.sh`, старый процесс после
`git reset` перезапускается уже новым файлом и только затем применяет конфиг.
Так миграция state не может выполниться старой логикой. Любой отказ после
определения целевого коммита записывает его SHA для Telegram-алерта.

Секреты живут в `secrets/openclaw.enc.yaml` под SOPS + age, расшифровываются
только в tmpfs `/run/openclaw/env`. Приватный ключ — на VM в
`/root/.config/sops/age/keys.txt`, на Маке в `~/.config/sops/age/keys.txt`.

## Модель и провайдеры

```
основной : cloudru/deepseek-ai/DeepSeek-V4-Flash   (2,6–3,1 с)
резерв   : custom-bothub-chat/deepseek-v4-flash    (5,18 с)
```

Cloud.ru стоит в том же облаке, что и VM. BotHub остаётся, пока на нём
есть остаток токенов. Резервный маршрут ни разу не проверялся под нагрузкой.

## Права бота

Базовый профиль `full` сразу сужается строгим `tools.allow`: разрешены только
`memory_search`, `memory_get`, `read`, `web_search`, `web_fetch`, `message`,
`cron`, `session_status`. `exec`, `process`, `write`, `edit`, `apply_patch` и
`browser` дополнительно запрещены в `tools.deny`.

Такая форма заменяет `minimal + alsoAllow`: в OpenClaw 2026.7.1 секции
`tools.fs` больше не расширяют minimal-профиль и тот печатает предупреждение
на каждый запрос. Итоговый набор инструментов не расширился. `read` по-прежнему
ограничен `tools.fs.workspaceOnly: true`, иначе он может дотянуться до
`openclaw.json` и `auth-profiles.json`.

Доступ к боту двухступенчатый: парринг даёт переписку,
`channels.telegram.allowFrom` плюс `commands.allowFrom` — команды.
Без второго списка все `/команды` молча игнорируются.
`commands.ownerAllowFrom` — только владелец.

## Состав репозитория

```
config/openclaw.batch.json     декларативные пути, применяются целиком
config/openclaw.unset.txt      ключи, которые GitOps должен удалить из state
config/workspace/              AGENTS.md · SOUL.md · IDENTITY.md — 6764 из 7000 байт
config/workspace/skills/       about · term · digest · sources · knowledge · analyze
config/knowledge/              ai-glossary · finance-glossary · models · sources
extensions/glossary-ui/        детерминированный Telegram-интерфейс, минуя модель
extensions/tavily-provider/    активный web_search через отдельный прокси
deploy/                        reconcile.sh + systemd-юниты
```

`AGENTS.md` — только маршрутизация. Подробности лежат в скиллах и читаются
с диска при вызове, а не висят в каждом промпте. Лимит 7000 байт проверяет CI.

## Поиск

`tools.web.search.provider = tavily`. Локальный provider отправляет только
запросы Tavily через `TAVILY_PROXY_URL`; Telegram, Cloud.ru и остальные
соединения gateway идут напрямую. Прокси не назначается глобальным dispatcher.
Reconcile проверяет регистрацию provider и наличие обеих переменных окружения,
но не тратит Tavily-квоту каждые пять минут. Полный сетевой тест запускается
вручную через `deploy/check-tavily.sh`.
Оба скилла, зависящих от поиска, имеют ветку отказа и не рассказывают
пользователю про провайдеры.

После общего `/healthz` + `/readyz` reconcile запускает отдельный Telegram
health gate: проверяет загрузку плагина и `channels status --probe`. Успех —
только если канал одновременно `running` и `works`; тот же тест вручную
запускается через `deploy/check-telegram.sh`. Это закрывает ложнозелёное
состояние, когда HTTP-gateway готов, но бот не принимает сообщения.

Там же проверяется `glossary-ui`: деплой падает, если `hookCount` нулевой или
`reply_dispatch` не попал в `typedHooks`. Без этой проверки интерфейс может
быть полностью мёртв при зелёном health gate — так уже было.

DuckDuckGo остаётся включён и настроен как ручной rollback. Автоматического
переключения нет: оно маскировало бы деградацию Tavily и снова могло привести
к капче на HTML-поиске.

## Интерфейс

Меню и каталог используют нативные callback-кнопки Telegram, и они работают:
клик редактирует сообщение на месте, не доходя до модели. Markdown deep links
остались только у переносимых ссылок на смежные термины.

`glossary-ui` перехватывает `reply_dispatch` до раскрытия workspace-скилла и
до модели. Поэтому `/start`, `/menu`, `/about`, `/knowledge`, `/sources`,
`/explain`, `/term` и известные локальные термины отвечают без LLM. Из команд
видимого меню модель запускают только `/digest` и `/analyze`; неизвестный
термин, написанный обычным текстом, по-прежнему уходит агенту.

Критерий работоспособности — не «бот ответил», а отсутствие
`provider-transport-fetch` в логах на статическую команду.

Эмодзи — разметка блоков с закреплёнными значениями, словарь в `SOUL.md`.

### Контракт регистрации плагина

Два требования SDK, каждое из которых по отдельности роняло весь интерфейс:

**Интерактивный хендлер обязан иметь `name`.** Без него
`registerInteractiveHandler` бросает `hook registration missing name`,
исключение уходит из `register()`, и плагин целиком помечается
`failed to initialize` — вместе с хуком, который регистрировался следующей
строкой.

**`reply_dispatch` подключается через `api.on`, а не `api.registerHook`.**
Это типизированный хук с сигнатурой `(event, context)`. Legacy-`registerHook`
принимает произвольную строку события, кладёт хук в `customHooks` с
`hookCount: 0` и вызывает обработчик одним envelope-аргументом: `context`
оказывается undefined, детерминированный ответ молча теряется.

Диагностика обоих случаев — `plugins inspect glossary-ui --runtime --json`.
Смотреть надо на `typedHooks` и `hookCount`, а не на `status`: у упавшего
плагина `status` остаётся `loaded`, а `hooks list` показывает `✓ ready` для
хука, не привязанного ни к одному событию.

## Что проверяет CI

Шестнадцать проверок. Утечки секретов, шифрование SOPS, shellcheck,
yamllint, валидность JSON и systemd-юнитов, `docker compose config`,
непубликация порта наружу.

Плюс семантические, кодирующие принятые решения: отсутствие дублей
в batch-конфиге, бюджет инструкций, согласованность меню со скиллами
и allowlist, топология провайдеров, декларативность поиска, регистрация
`reply_dispatch` через `api.on`.

Каждая семантическая проверка появилась после реальной поломки.

Тесты плагина проверяют форму вызова, а не только результат: поддельный `api`
обязан бросать при отсутствии `name` и при legacy-регистрации. Иначе тест
подтверждает согласованность выдумки с собой — так и пропустили обе поломки
интерфейса.

## Чего не хватает

- `/analyze` и переписанный `/digest` не проверены на живых данных
- Cloud.ru отдаёт `429` под нагрузкой, и фолбэк на BotHub при этом
  не включается: рантайм ретраит ту же модель с задержками 10 и 20 секунд.
  Под ударом ровно `/digest` и `/analyze` — единственные команды, которые
  теперь доходят до модели
- после каждой замены или продления прокси нужно запускать
  `deploy/check-tavily.sh` на VM
- покрытие квоты Cloud.ru не подтверждено — карта личная, потолка нет
- Telegram-идентификатор председателя не добавлен в оба списка доступа,
  а `dmPolicy: allowlist` означает, что без этого он не сможет даже написать
- бэкап состояния только ручной: реконсиляция восстановит инфраструктуру,
  но не парринг, auth-профили и индекс памяти
- ошибки регистрации плагинов пишутся только в `/tmp/openclaw/*.log` внутри
  контейнера; лог эфемерный, в Control UI его нет

## Решения, которые лучше не пересматривать

Каждое стоило нескольких часов.

**Источник истины — бинарник, а не документация и не догадка.** Расхождения
с сайтом были пять раз по конфигу (`memory.search` против
`agents.defaults.memorySearch`, `paths` против `extraPaths`, несуществующий
провайдер `none`, группа `group:memory`, `customCommands` не под `commands`)
и дважды по SDK плагинов. Проверять `openclaw config schema`, `plugins inspect
--runtime --json`, `hooks list` и исходники bundled-плагинов в `/app/dist`.

**Ошибка применения конфига обязана ронять деплой.** Было
`|| log "ВНИМАНИЕ"` — реконсиль считался успешным при незаявленном конфиге.

**Зелёный health gate должен означать работающий продукт, а не живой
процесс.** `/healthz` и `/readyz` не знают ни про Telegram, ни про плагины.
Отсюда отдельные проверки канала, Tavily и typed-хука `glossary-ui`.

**Рестарт гейтвея — только при реальном изменении конфига.** `config set`
переписывает `meta.lastTouchedAt` каждый раз, и ориентация на текст вывода
CLI давала рестарт каждые пять минут с обрывом диалогов.

**Подключение человека — два действия.** Парринг даёт переписку,
`channels.telegram.allowFrom` — команды. Без второго все `/команды` молча
выбрасываются.

**Инструкции под 7000 байт.** Уходят в каждый вызов, вызовов на ответ больше
десяти. Детали — в скиллы, справочные данные — в базу знаний.

**Публикация меню и его исполнение — разные владельцы.**
`channels.telegram.customCommands` объявляет список, `glossary-ui` исполняет.
Регистрация команд плагином поверх этого даёт конфликт владения.
