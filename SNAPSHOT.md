## Что это

**Glossaryck** — Telegram-бот на OpenClaw. Объясняет термины ИИ и финансов
из своей базы, собирает дайджест новостей, разбирает релизы моделей.
Аудитория — один-два человека, включая председателя, для которого важнее
всего внешний вид и понятность.

MVP сдаётся 14 августа. После сдачи расходы прекращаются.

## Инфраструктура

| Что | Где |
|---|---|
| VM | Cloud.ru, Ubuntu, 4 ГБ / 30 ГБ |
| Рантайм | Docker Compose, образ запинен по digest |
| Репозиторий | `F8Y/openclaw-glossary`, ветки `master` → `deploy` |
| Клон на VM | `/opt/openclaw-glossary`, deploy-ключ только на чтение |
| Порт гейтвея | `127.0.0.1:18789` — наружу не публикуется |
| Telegram | `extra_hosts` пинит `api.telegram.org` на `149.154.167.220` |

## Как выглядит доставка

```
git push master → CI → ручной Promote → ветка deploy
                                            ↓
        systemd-таймер раз в 5 минут → reconcile.sh
                                            ↓
   git reset --hard → SOPS в tmpfs → config → rsync → health-gate
```

Реконсиляция безусловная: состояние сервера приводится к ветке `deploy`
независимо от того, менялось ли что-то. Ручная правка на сервере
затирается — это задумано.

Секреты живут в `secrets/openclaw.enc.yaml` под SOPS + age, расшифровываются
только в tmpfs `/run/openclaw/env`. Приватный ключ — на VM в
`/root/.config/sops/age/keys.txt`, на Маке в `~/.config/sops/age/keys.txt`.

## Модель и провайдеры

```

резерв   : custom-bothub-chat/deepseek-v4-flash    (5,18 с)
```

Cloud.ru стоит в том же облаке, что и VM. BotHub остаётся, пока на нём
есть остаток токенов. Резервный маршрут ни разу не проверялся под нагрузкой.

## Права бота

Профиль `minimal`. Запрещено: `exec`, `process`, `write`, `edit`,
`apply_patch`, `browser`. Разрешено: `memory_search`, `memory_get`, `read`,
`web_search`, `web_fetch`, `message`, `cron`, `session_status`.

`read` нужен скиллам для прогрессивного раскрытия, поэтому оставлен,
но ограничен `tools.fs.workspaceOnly: true` — иначе он дотягивается
до `openclaw.json` и `auth-profiles.json`.

Доступ к боту двухступенчатый: парринг даёт переписку,
`channels.telegram.allowFrom` плюс `commands.allowFrom` — команды.
Без второго списка все `/команды` молча игнорируются.
`commands.ownerAllowFrom` — только владелец.

## Состав репозитория

```
config/openclaw.batch.json     71 декларативный путь, применяется целиком
config/workspace/              AGENTS.md · SOUL.md · IDENTITY.md — 6764 из 7000 байт
config/workspace/skills/       about · term · digest · sources · knowledge · analyze
config/knowledge/              ai-glossary · finance-glossary · models · sources
extensions/glossary-ui/        детерминированный Telegram-интерфейс, минуя модель
extensions/tavily-provider/    провайдер поиска, включён, но недостижим
deploy/                        reconcile.sh + systemd-юниты
```

`AGENTS.md` — только маршрутизация. Подробности лежат в скиллах и читаются
с диска при вызове, а не висят в каждом промпте. Лимит 7000 байт проверяет CI.

## Поиск

`tools.web.search.provider = duckduckgo`. HTML-выдача, иногда отдаёт капчу.
Оба скилла, зависящих от поиска, имеют ветку отказа и не рассказывают
пользователю про провайдеры.

`tavily-provider` написан и включён, но недостижим: AWS ELB отвечает `403`
на запросы с российского IP — блокировка до API, ключ ни при чём.
Переключение обратно — одно значение `provider`.

## Интерфейс

Кнопки Telegram сделаны markdown-ссылками вида
`https://t.me/glossary_ai_bot?start=term_ROE`. Callback-кнопки в этой сборке
отрисовываются, но до агента не доходят.

Статические экраны (`/start`, `/menu`, `/about`, `/knowledge`, `/sources`,
`/explain`) перехватывает `glossary-ui` до модели — мгновенно и без расхода
токенов. Остальное идёт агенту.

Эмодзи — разметка блоков с закреплёнными значениями, словарь в `SOUL.md`.

## Что проверяет CI

Шестнадцать проверок. Утечки секретов, шифрование SOPS, shellcheck,
yamllint, валидность JSON и systemd-юнитов, `docker compose config`,
непубликация порта наружу.

Плюс семантические, кодирующие принятые решения: отсутствие дублей
в batch-конфиге, бюджет инструкций, согласованность меню со скиллами
и allowlist, топология провайдеров, декларативность поиска.

Каждая семантическая проверка появилась после реальной поломки.

## Чего не хватает

- `/analyze` и переписанный `/digest` не проверены на живых данных
- резервный маршрут на BotHub не проверен принудительным отказом основного
- покрытие квоты Cloud.ru не подтверждено — карта личная, потолка нет
- Telegram-идентификатор председателя не добавлен в оба списка доступа,
  а `dmPolicy: allowlist` означает, что без этого он не сможет даже написать
- бэкап состояния только ручной: реконсиляция восстановит инфраструктуру,
  но не парринг, auth-профили и индекс памяти
